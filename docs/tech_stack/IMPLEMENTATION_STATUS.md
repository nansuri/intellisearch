# Implementation Status

**As of:** 2026-08-17
**Overall status:** Early MVP implementation; M2–M4 (public UI, AI pipeline, Owner Control Panel) are now delivered. M5 hardening items remain.

This document is the implementation truth for the repository. The PRD and SDD remain the target product/design specification; a checked item below means the behavior exists in code, not merely in planning documentation.

## Delivered

### Frontend — public pages

- Vue 3, TypeScript, Vite, Vue Router, and Pinia bootstrapping.
- Public routes: `/`, `/search`, `/login`, and `/account`.
- Clean/premium visual revamp for the public pages, with responsive layouts and light/dark/system theme tokens.
- Reusable `AppHeader`, `AskBox`, `UrlAskBox`, `ErrorBanner`, `BaseButton`, `Tabs`, `ThemeToggle`, `SourceCard`, and new shared form/modal/chart primitives.
- Main page simplified to a Google-like centered search entry point, with an **Ask AI / Search mode toggle** — "Ask AI" runs the full pipeline (SearXNG + crawler + LLM synthesis with citations), "Search" returns raw web results only (no crawler, no LLM, so it stays fast and works even when the AI provider is down).
- **Result page wired to the real AI API:** asks the query on load, renders the cited answer + a **Google-style "Read more" list** (web icon tile, title link, green domain, and description with the **query's significant terms highlighted** in `<mark>`), paginated at **10 results per page** (numbered pager), follow-up thread (same `sessionId`), skeleton loading, friendly error banner with retry, and a URL-read box in the no-sources state.
- **Account settings wired to the API:** sign-in-gated profile view (name/email edit, avatar upload with initials fallback), daily AI usage meter with quota, session tab with logout and (for Super Owners) a control-panel shortcut.
- **Unified sign-in page (`/login`):** one glass-themed auth page for every account type — Super Owners sign in here too (the old `/admin/login` redirects here) and reach the control panel via their account menu. After signing in everyone lands on the **main page** (previously `/account`).
- **Google SSO (optional):** `GET /api/v1/auth/google` starts the OAuth authorization-code flow (CSRF `state` in an httpOnly cookie); the callback exchanges the code, finds-or-creates the user, issues the app JWT, and redirects to `/auth/callback?token=…` which completes the session and lands on the main page. New Google accounts become `general_user` with no usable password; disabled when `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` are unset (`AUTH01003`).

### Frontend — Owner Control Panel (SDD M4)

- **Registration:** the same auth page adds a **Create account** tab (`/login?mode=register`, `/register` redirects there) — name + email + password (≥ 8 chars) creates a `general_user` via `POST /api/v1/auth/register` (`AUTH01004` invalid data, `AUTH01005` duplicate email) and lands the user signed in. **Google SSO registers too**: the OAuth callback find-or-creates the account, so "Sign up with Google" works with zero extra backend setup.
- **Authenticated admin shell** (`ControlPanel`): persistent sidebar on desktop (≥1024 px) with a **parent → child accordion** (expandable/collapsible groups, active parent auto-expanded, active child highlighted); below 1024 px it collapses into a **hamburger-triggered slide-in drawer with a backdrop overlay**, the current page name is shown in the header, and selecting a page navigates and closes the drawer. **The control panel shares the main site's design tokens** — it no longer overrides the palette with its own violet/slate colors; it inherits the global `tokens.css` set (same primary, backgrounds, borders, danger, etc. in both themes, only adding the admin-specific `--color-warning` and a primary-derived background glow). Primary/danger buttons and gradient marks use `--color-primary-contrast` so text stays readable on the (light-blue) dark-mode primary; the trending-words chart leads with the global primary token.
- **User management** (`/admin/users`, `/admin/users/suspended`): debounced search, pagination, create/edit modal (name, email, password on create, role, daily quota), suspend/reinstate/delete with confirmation modals, live refresh on focus.
- **Statistics** (`/admin/stats`, `/admin/stats/visitors`, `/admin/stats/words`, `/admin/stats/usage`, `/admin/stats/ai`): overview stat cards + **daily (7-day) and weekly (8-week) trend bar charts**, top-query (masked) and heaviest-user charts, full top-queries list, **Trending words page with a grouped-bar term chart + top-terms list (daily/weekly toggle)**, per-user usage table with usage bars, and an AI-service page (success/failure rate, per-provider performance, **error-code grouping with a filter-by-type dropdown**, latency percentiles, queue health).
- **Unique users & visitors (replaces the masked Top queries page):** the sign-in page records — best-effort and idempotent per visitor — every unique visitor that opens the **Create account** tab (`POST /api/v1/stats/register-visit`, reusing the anonymous AI guest token; replays are deduped server-side by a unique `visitor_id`). The new **`/admin/stats/visitors`** page shows registered accounts, active users (all-time + 7d), unique anonymous AI visitors, and unique register-page visitors with **daily/weekly trend charts**, and the Overview gains a "Unique users & visitors" summary comparing registration interest vs. conversion. The **masked `Top queries` page was removed** (the privacy-safe **Trending words** page remains the query-insights view); the API's masked `topQueries` field is unchanged for backward compatibility. New endpoints: `POST /stats/register-visit`, `GET /admin/stats/visitors`; error codes `STTS01001/2`.
- **AI providers** (`/admin/ai/providers`): create/edit/delete provider cards with type (Ollama / OpenAI-compatible / **Pollinations.ai** / **Hugging Face**), auto-filled endpoint + model presets per type, base URL, model, JSON model parameters, encrypted API key (blank keeps existing; hidden for keyless providers), and single-click "set active" routing. **Ollama providers get a live server inspector**: a "Load models & health" button (auto-loads on open) fetches the model list (`GET /api/tags`) plus a health card with the server version and loaded-model CPU/GPU/memory stats (`GET /api/version` + `/api/ps`) — all proxied through the Go API (`ADMN06001`), never direct from the browser. The **Model field becomes a real `<select>` dropdown** once the server's models are loaded (with the current model kept selectable when it no longer exists on the server, plus a "Type a custom model…" escape hatch); without a loaded list it stays a text input.
- **Pollinations account panel (specialized handler):** when the provider type is **Pollinations.ai**, the provider form gains a "Pollinations account" card — **credits/pollen balance**, key validity/type/expiry/budget, the account profile (GitHub username, name, email when the key has `account:profile`), and a **last-14-days usage summary** (requests + $ cost per day). A **new specialized `PollinationsHandler`** sits alongside the AI handler (which remains the single interface for AI work): it proxies `GET /account/balance` + `/account/profile` + `/account/key` (`POST /admin/ai/pollinations/account`), `/account/usage` and `/account/usage/daily` (`/usage`, `/usage/daily`), `GET /v1/models` (`/models` — feeds the provider form's model dropdown, like Ollama), and image uploads to `media.pollinations.ai` (`/upload`, multipart; `POLLINATIONS_MEDIA_BASE_URL` overrides the host). Credentials resolve from a saved provider's **encrypted key (decrypted server-side, never sent to the browser)** via `providerId`, or from `{ apiKey, baseUrl }` while configuring an unsaved provider. Errors: `ADMN07001` (unreachable), `ADMN07002` (key rejected), `ADMN07003` (upload failed).
- **Queue & limits** (`/admin/ai/queue`): edit `max_concurrent`, `max_queue_size`, `request_timeout_ms`, `per_user_rate_limit`, `suggestion_cache_hours` (how long the main page's AI suggestions are reused before recomposing), `default_daily_quota` (daily AI usage granted to newly registered accounts — default 3, 0 = unlimited), and `max_image_results` (image results per search — default 20, 0 = unlimited) with immediate apply — no redeploy.
- **Branding** (`/admin/branding/identity`, `/admin/branding/logo`): site name/tagline editing with live preview, a **copyright line** (the footer's `© <year> <text>`, blank falls back to the site name), logo upload with drag & drop, and **logo removal (delete → falls back to the default initials mark)**; all apply to the public main page immediately (site store refresh). **Re-uploading a logo/favicon/avatar now works**: every upload gets a unique filename (`<id>-<nonce>.<ext>`), so the URL changes and the browser can't serve the old cached image (previously `logo.png` kept the same URL and the old image lingered); the replaced file is deleted best-effort.
- **Site footer:** every page renders a footer with `© <year> <configured copyright>` (from `site_settings.copyright`, configurable in Branding → Identity; falls back to the site name). A flex app frame pins it to the bottom of short pages.
- **Mobile layout fixes:** the sticky header full-bleed pattern no longer double-shrinks (removed `width: 100%` on `.header-bar`, which over-constrained the block box and left a right-side gap), and the compact result-page header declares all three grid columns at ≤850 px so the ask box spans the full row instead of collapsing to its content width (the `header-actions` implicit third column broke `grid-column: 1 / -1`). Plus: brand link truncates gracefully, admin/CP buttons compact, auth card padding tightens, image grid switches to smaller tiles, and `empty-sources` stacks — all verified at 375 px (no horizontal overflow on the main, result, or auth pages).
- Frontend auth store (JWT in localStorage, `restore()` on boot, 401 expiry handling), admin router guards, typed API client with friendly per-error-code messages, and a toast notification system reused across the panel.
- **Session persistence on hard refresh:** the router guard restores the user whenever a token exists but the in-memory profile is missing, so a reload no longer appears to log the user out.
- **PWA / installable app:** the frontend ships a **service worker + precached app shell** (vite-plugin-pwa; static assets only — API/uploads/manifest navigations are never intercepted) and the Go backend serves **`/manifest.webmanifest`** at the frontend origin rendered from the live `site_settings` branding (site name, tagline, uploaded logo), with `pwa-192x192.png`, `pwa-512x512.png`, `pwa-maskable-512x512.png`, and `apple-touch-icon.png` icons (generated by `frontend/scripts/gen-pwa-icons.mjs`, matching favicon.svg). Android Chrome and iOS Safari can install the site as a standalone app; the manifest is `no-cache` so branding edits propagate immediately. nginx proxies `/manifest.webmanifest` to the API; the dev server proxies it too.
- **Mini apps (app drawer):** the header gains a top-right **app drawer** (grid icon, signed-in users) opening the mini apps. **Notes** (`/notes`): personal notes with a card grid, create/edit modal, two-step delete, and relative timestamps; the result page's **"Save summary to notes"** button saves the current answer as a note linked back to the search (`sourceQuery`/`sessionId`). **Translator** (`/translator`): a Google-Translate-style two-panel UI (source textarea with detect-language + char count, target output with copy, swap button, debounced translation) proxied **server-side** through the Go API to the LibreTranslate container — the browser never talks to it directly. Both apps are auth-gated; translator is rate-limited per user.
- **Login UX (glass theme):** the auth page was fully revamped — animated aurora blobs, a frosted-glass card with backdrop blur, translucent glass inputs and buttons, and a segmented Sign in / Create account switcher with slide transitions, success checkmark animation, and error banners (including Google OAuth failures via `?error=`). All animations respect `prefers-reduced-motion`.
- **Search history:** every non-URL ask by a signed-in user is recorded in a dedicated `search_history` table (separate from `usage_logs` so admin stats/quotas are unaffected). The main page shows the user's **recent searches** as clickable chips under the ask box, plus **AI-composed suggestions** derived from their history (refreshable via a ↻ button, gracefully hidden when the provider is down or history is empty). The main page's suggestion row is reachable from the **profile menu → Search history**, which opens the dedicated **`/history` page**: the full history (up to 100) with an on-demand **answer summary** per search (the linked assistant message, truncated — only the message ID is stored in `search_history`, so no answer text is duplicated) and a **Clear history** button with confirmation. **Account Settings** keeps a recent-searches preview with timestamps and clear, plus an "Open full history" link.
- **Suggestion caching (configurable):** AI-composed suggestions are cached **server-side per user** for `suggestion_cache_hours` (`ai_queue_config`, default 6, 0 = always compose fresh) instead of calling the LLM on every main-page visit. The Owner Control Panel → Queue & limits page edits the window with immediate effect; clearing history also drops the user's cached suggestions. `GET /api/v1/me/history/suggestions?refresh=1` bypasses the cache.
- **Default daily quota (admin-configurable):** newly registered accounts (password or Google SSO) start with **3 AI asks/day** — the `default_daily_quota` knob on the Queue & limits page (0 = unlimited), applied at sign-up and editable anytime (affects only accounts created afterwards). Per-user quotas remain individually overridable under User management.
- **Admin privacy — masked queries + trending words:** the control panel never shows verbatim user queries. `topQueries` in `GET /admin/stats` are **masked** (first rune + `*`s) while keeping counts, and a new **Trending words** page (`/admin/stats/words`) tokenizes sanitized queries into lowercase terms (stopwords/short words dropped) aggregated per day (7 buckets) or week (8 buckets) — rendered as a grouped bar chart plus a top-terms list. New endpoint: `GET /admin/stats/trending-words?window=daily|weekly` (`{ window, buckets[], overall[] }`); the API never returns a raw query.
- Endpoints: `GET/PATCH/DELETE /api/v1/me/history` + `GET /api/v1/me/history/suggestions`; error codes `USER03001/2`.

### Backend foundation

- Go/Gin API with the common response envelope and typed error-code catalog (`<FEATURE><SUBSET><ERROR>` format enforced by a unit test over `contracts/errors.go`).
- Logrus startup/recovery logging and configured CORS middleware.
- GORM AutoMigrate and idempotent seeds for users, site settings, AI queue configuration, providers, chat sessions, messages, search results, usage logs, and crawl jobs. Singleton seeds (`site_settings`, `ai_queue_configs`) look up by primary key only, so admin-edited rows (custom branding, tuned queue knobs) survive reboots instead of being re-inserted.
- Database selection by environment: local host-run defaults to SQLite; production and Docker API services explicitly use PostgreSQL.
- Site branding endpoint reads persisted `site_settings` rather than hardcoded response data.
- JWT login, authenticated profile read/update, avatar upload, and Super Owner role middleware.
- Admin endpoints for user CRUD, statistics, provider CRUD, queue config, site settings, and logo upload (each route requires Super Owner); logo deletion returns branding to the default mark.
- `GET /api/v1/admin/stats/trends` returns daily/weekly question counts (bucketed in the service so SQLite and PostgreSQL behave identically).
- **Configurable session lifetime:** signed-in JWT sessions default to **7 days** (was 24 h) and the Super Owner can change the duration live from the Owner Control Panel (Queue & limits → Account session) via the new `session_ttl_hours` knob on `ai_queue_configs` — no redeploy. The active provider setting takes priority over the deployment `JWT_TTL_HOURS` env value (0 = fall back to it); it applies to sessions signed in after the change, and already-issued tokens keep their original expiry.
- SearXNG JSON client with source/domain mapping.
- Go URL validation and crawler-side URL validation for SSRF protection.

### AI pipeline (SDD M3)

- **Single AI handler** (`internal/handlers/ai_handler.go`) as the only entry point for AI work, owning a **worker pool + bounded queue** whose knobs (`max_concurrent`, `max_queue_size`, `request_timeout_ms`, `per_user_rate_limit`) are read from `ai_queue_configs` with a 5-second cache — admin edits take effect without redeploying (verified live: DB edit applied within ~5s without restart).
- **`POST /api/v1/ask`** and **`POST /api/v1/ask/url`** implemented end to end: session/message/usage-log persistence, SearXNG search → source cards, deep-read of top N pages through the crawler, LLM synthesis with inline citations, and typed error mapping with sanitized client messages. The `mode` field supports **`"search"`** — **AI-free**: an **extractive summary composed from the top SearXNG snippets** (no crawler, no LLM call, no provider attribution) so quick answers cost zero AI tokens — and the default **`"enhanced"`** (full pipeline).
- **Image results:** the **primary** search of a thread (both modes) also queries SearXNG's **images** category (`categories=images`) best-effort; results are capped by the admin-configurable `max_image_results` (default 20), persisted as `image_results` per message, and returned as `images` in the ask/session responses. **Follow-up asks skip the image search entirely** (no second grid, no wasted SearXNG calls). The result page shows **Google-style tabs (All / Images)** under the query — All renders the answer + Read more list, Images a responsive grid (thumbnails browser-loaded — the API never fetches third-party images). Clicking a thumbnail opens a **full-screen lightbox** (full-size `fullUrl` when available, else the thumbnail) with prev/next navigation, keyboard arrows, a **download** button (blob fetch, falling back to opening the image directly when CORS blocks it), and a source-page link; thumbnails that fail to load are **dropped from the grid** automatically. An image-search failure never fails an ask.
- **Map for location-aware queries:** when the query is "near me"-style and the user shared their device position, the backend builds a **map**: the center is the user's location (reverse-geocoded label, position 0) and the markers are the top 5 source titles geocoded via Nominatim search, kept only when within 100 km of the user (max 6) — persisted as `map_points` per message and returned as `mapCenter`/`mapMarkers`. The result page renders an **interactive Leaflet map** (OSM tiles, no API key; `VITE_MAP_TILE_URL` overrides the tile server) with a "you" pin and numbered result pins with popups, plus an "Open in OpenStreetMap" link — in the AI overview, the search-only summary, and follow-up entries. Map building is best-effort: geocoding failures only mean fewer markers.
- **AI-generated visuals inside answers:** the LLM prompt now permits **Mermaid diagrams** (fenced `mermaid` blocks), **ASCII art**, and **Markdown tables** whenever a chart/diagram makes the answer clearer. The frontend renders Mermaid fences **client-side** (lazy-loaded `mermaid` package, theme-aware, code-split out of the main bundle), falling back to the raw fenced block on parse errors.
- **Follow-up vs new search:** the result page labels the primary query **"New search"** and each thread entry **"Follow-up N"** with distinct badges; the header ask box gains a **send-mode toggle beside the Ask button** (Follow-up ↔ New search) — Follow-up continues the thread, New search clears it and runs the typed question fresh.
- **LLM provider abstraction** (`internal/services/llm_service.go`): Ollama (`/api/chat`) plus OpenAI-compatible clients — OpenAI-compatible (`/v1/chat/completions`), **Pollinations.ai** (`/v1/chat/completions`, Bearer key required, base `https://gen.pollinations.ai`), and **Hugging Face** (`/chat/completions`, Bearer key); provider API keys decrypted at call time from AES-GCM storage.
- **CrawlService** (`internal/services/crawl_service.go`): SSRF-guarded URL validation, `crawl_jobs` lifecycle (queued → running → completed/failed/blocked), best-effort parallel deep-read of the top sources.
- **Redis sliding-window rate limiter** (per-user or per-IP; URL submission capped at 5/hour) and **per-user daily quota** (`ai_daily_quota`, 0 = unlimited) enforced before enqueue.
- **Anonymous guest limit (1 AI usage):** non-logged-in callers get exactly one AI ask. Layered, fraud-resistant enforcement: a server-issued `visitor_id` (returned as `visitorId` in the response and mirrored in an httpOnly 1-year cookie) blocks repeat use even after localStorage is cleared; a unique `anonymous_usage` row per hashed IP blocks cookie+storage clearing from the same network; and `TRUSTED_PROXIES` restricts which proxies may supply `X-Forwarded-For`, so public clients can't spoof a fresh IP. Only a successful ask consumes the allowance (failed asks release the claim so an outage doesn't burn it). DB-backed (independent of Redis), signed-in users exempt, `mode=search` free. Rejection → 429 `AISY02004` with a friendly sign-in message; the result page renders a **Sign in to keep searching** CTA.
- **`GET /api/v1/sessions/:id`**: owner-only session retrieval with message history and per-message `search_results`.
- Runtime queue metrics (`queueDepth`, `inFlight`, `rejected`, `maxConcurrent`) exposed on the handler for the admin AI-stats page.
- Graceful degradation: SearXNG down → the LLM still answers without web sources.
- Error codes: `AISY01001/2/3/4`, `AISY02001/2/3`, `AISY03002/3/4`, `SESS01001/2`, plus `AUTH*`, `USER*`, `SITE*`, and `ADMN*`.

### Runtime and documentation

- Local script provisions Redis, SearXNG (host 8081 → container 8080), and the Playwright crawler (host 3001 → container 3002, image built from `crawler/`) via Podman and uses `backend/data/intellisearch.db` for SQLite; `SEARXNG_BASE_URL=http://localhost:8081` and `CRAWLER_BASE_URL=http://localhost:3001` are exported for the host-run backend (Docker Compose overrides both to the internal service names).
- Host-exposed ports avoid the commonly occupied set: the API listens on **8088** (was 8080) and the production frontend on **8082** (was 80); SearXNG and the crawler stay internal-only inside the Docker network, so no host conflict. Postgres (5432) and Ollama (11434) are reused external containers, not deployed by this stack.
- Production Compose sets `DB_DRIVER=postgres`; the API service's `env_file` resolves `${ENV_FILE:-.env}` so `deploy-prod.sh` injects the gitignored `.env.production` (strong secrets) instead of the dev `.env`. The stack deploys only its own services — PostgreSQL and Ollama are reused: the API attaches to external `SHARED_DB_NETWORK` and `OLLAMA_NETWORK` networks (no DB/Ollama service in `docker-compose.prod.yml`). All three Dockerfiles build (`backend` on `golang:1.25` with `-p 2` compile parallelism for small hosts, `frontend` via `npm run build` → nginx, `crawler` via `npm ci` with its generated `package-lock.json`).
- **Uploads work in production:** the API image pre-creates `/uploads` (branding + avatars) owned by the unprivileged nonroot user and sets `UPLOADS_DIR=/uploads`; the prod compose mounts a named `uploads` volume there so logos/favicons/avatars **persist across redeploys**, and nginx proxies `/uploads/` back to the API so the relative upload URLs resolve on the public origin. Upload failures log the underlying cause (`ADMN05002`/`ADMN05003`/`USER02001` no longer hide the reason).
- API contract, UI revamp proposal/SDD, and this status document are maintained under `docs/`.
